# Русские тематические названия в Scientific Intelligence Lab

## Назначение

Слой тематической интерпретации формирует понятные русские названия сообществ по заголовкам и аннотациям публикаций. Он работает после кластеризации и не меняет `clusters.csv`, идентификаторы групп, назначения документов, граф или матрицу SPECTER.

## Что изменено в версии 1.2.0

### 1. Отдельное ранжирование терминов для названия

Исходный `score` извлечения не перезаписывается. Для выбора пользовательского названия рассчитывается отдельный `naming_score`, который учитывает:

- исходный рейтинг кандидата;
- распространённость понятия внутри сообщества;
- поддержку в заголовках;
- контрастность относительно других сообществ;
- специфичность формулировки;
- штраф за слишком общие и служебные фразы.

Кандидаты с выражениями вроде `United States`, `percentage points`, `success rate` и `lower bounds` не допускаются к формированию публичного названия. Варианты написания, единственное/множественное число и распространённые сокращения сводятся к каноническим понятиям. Поддержки синонимов не суммируются: такие фразы могут встречаться в одних и тех же документах.

### 2. Русская терминология без некорректного пословного перевода

Для устойчивых научных терминов используется курируемый словарь и правила составления названий. Неизвестная фраза сохраняется на английском, вместо рискованного перевода каждого слова по отдельности: это предотвращает грамматически неправильные и смыслово неточные сочетания. Словарь находится в `topic_naming.py` и может расширяться.

### 3. Дополнительные понятия, которые теряются из-за стоп-слов

Небольшой детерминированный набор лингвистических шаблонов распознаёт понятия вроде `AI and the Economy`, `computational biology`, `medical artificial intelligence` и `LLM agents`. Эти концепты добавляются только в матрицы извлечения кандидатов.

Ключевой момент корректности: если концепт найден только в аннотации, он не считается присутствующим в заголовке. Поэтому `title_support_docs` не завышается синтетическими признаками из abstract. Это покрывается отдельными тестами.

### 4. Сохранение доказательств и исходной терминологии

В `group_topic_profiles.csv`:

| Поле | Значение |
|---|---|
| `automatic_label` / `automatic_label_ru` | Основное русское название для интерфейса |
| `automatic_label_en` | Английское название для аудита |
| `automatic_description` / `automatic_description_ru` | Русское описание |
| `topic_aspects` / `topic_aspects_ru` | Дополнительные тематические аспекты на русском |
| `topic_aspects_en` | Исходные английские понятия |
| `naming_confidence` | Категориальная эвристическая оценка уверенности |
| `naming_confidence_score` | Рейтинг ведущего кандидата, не вероятность |
| `naming_evidence` | JSON со свидетельствами для выбранных терминов |

В `topic_candidates.csv` сохраняются исходные англоязычные фразы, `score`, а также `canonical_phrase`, `canonical_phrase_ru`, `naming_score`, `specificity_score` и `generic_penalty`.

`automatic_label` теперь содержит русское название. Для скриптов и внешних потребителей, которым нужен старый язык, предусмотрено `automatic_label_en`.

## Пересчёт профилей текущего запуска

Из корня проекта:

```powershell
.\RUN_TOPIC_UNDERSTANDING.ps1
```

Команда ищет последний `clusters.csv` и сохраняет профили в соответствующую папку:

```text
artifacts/runs/<run_id>/semantic_profiles/
```

В Streamlit откройте страницу **«Тематические профили»** и нажмите **«Сформировать / обновить семантические названия»**. Это выполнит тот же расчёт для выбранного запуска.

CLI пытается загрузить канонические аннотации из локальной SQLite-базы. Если они недоступны, используется существующий локальный механизм извлечения текста и фиксируется источник текста.

## Техническая проверка

Из корня проекта в PowerShell:

```powershell
$env:PYTHONPATH = "src;."
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m py_compile topic_naming.py topic_understanding.py run_topic_understanding.py dashboard\app.py
```

Тесты проверяют перевод известных терминов, отказ от сомнительного пословного перевода, подавление служебных фраз, канонизацию синонимов, русские названия основных семейств тем, корректный учёт title support и неизменность исходных group ID.

## Ограничения

- Перевод детерминированный и словарный; неизвестные выражения могут остаться на английском.
- Шаблоны концептов — прозрачные лингвистические эвристики, а не полноценное понимание языка.
- `naming_score`, `naming_confidence` и `topic_profile_score` — диагностические эвристики, не калиброванные вероятности и не метрики качества кластеризации.
- Автоматическое название не является экспертной разметкой. Пограничные и смешанные группы должны сохранять статус проверки.
- Внутренние KMeans-подгруппы диагностические и не изменяют исходные назначения Louvain/HDBSCAN.
