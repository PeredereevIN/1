# Scientific Intelligence Lab — General Research Corpus

Чистая версия проекта для экспериментов с тематической группировкой научных публикаций. В комплект **не включены** старый корпус, исторические назначения кластеров, сохранённые SPECTER-векторы, прошлые эксперименты и отчёты. Все результаты формируются заново на данных, которые пользователь соберёт после установки.

## Что проверяем

Основная задача — не воспроизвести заранее известные 17 групп, а проверить, насколько алгоритмы самостоятельно восстанавливают тематическую структуру корпуса.

В проекте доступны два разных представления:

1. **Векторное пространство SPECTER** — каждый документ кодируется нормализованным вектором. HDBSCAN выделяет плотностные группы в исходном пространстве или в UMAP-представлении.
2. **Взвешенный граф сходства** — вершины соответствуют статьям, ребро соединяет близкие SPECTER-векторы, вес ребра равен cosine similarity. Louvain выделяет сообщества по структуре графа.

PCA/UMAP на карте — только координатная проекция для отображения. Она не подменяет исходные векторы при расчёте cosine similarity.

## Случайная выборка 1 870 статей

Скрипт `download_random_arxiv.py` загружает PDF из arXiv в `data/inbox/<topic>/`.

- 11 первичных категорий arXiv из разных областей.
- Число публикаций по темам случайно формируется распределением Дирихле (concentration=20) с заданным seed. Поэтому распределение намеренно неравномерное, но не задаётся вручную.
- Внутри каждой категории случайно выбираются публикации из пула последних доступных работ, у которых эта категория является **primary category**. Это случайная выборка из ограниченного недавнего пула, а не равномерная случайная выборка за всю историю arXiv. Seed делает квоты воспроизводимыми; фактический состав выборки фиксируется манифестом, поскольку пул arXiv меняется со временем.
- Seed и квоты сохраняются в `data/metadata/random_topic_distribution.json`.
- Для каждой статьи сохраняется JSON с arXiv ID, названием, аннотацией, авторами, категориями, DOI и адресом PDF. При ingest эти метаданные используются как канонические title/abstract, а извлечённый из PDF текст остаётся источником полного текста.
- Загрузка возобновляется по манифесту; уже скачанные файлы повторно не загружаются.
- Между запросами к arXiv выдерживается задержка 3 секунды по умолчанию; последовательная загрузка 1 870 PDF может занять около 1,5 часа или дольше, но процесс можно безопасно продолжить повторным запуском.

Для `seed=20261119`, `target=1870`, `concentration=20` генератор создаёт следующие квоты (они воспроизводимы и сохраняются в JSON):

| `cs.CV` | Computer Vision | 151 |

Запуск из PowerShell:

```powershell
.\DOWNLOAD_RANDOM_ARXIV.ps1
```

Или напрямую:

```powershell
.\.venv\Scripts\python.exe .\download_random_arxiv.py --target 1870 --seed 20261119
```

Можно указать контактный email для User-Agent:

```powershell
.\DOWNLOAD_RANDOM_ARXIV.ps1 -Email "your-email@example.org"
```

Для нового независимого набора с другим seed сначала архивируй или удали `data/inbox/<topic>/` и `data/metadata/`, затем запусти скрипт с новым seed. Скрипт намеренно не смешивает разные планы выборки автоматически.

**Важное ограничение:** arXiv primary category — это слабая внешняя метка, а не безошибочная истинная тема каждой статьи. Категории пересекаются, а некоторые статьи имеют междисциплинарный характер. Поэтому ARI/NMI и purity показываются как вспомогательные показатели согласованности с источником, а не как абсолютная оценка качества тематического разбиения.

## Установка

Требуется Python 3.12 и Windows. Для RTX 4070 устанавливается CUDA-сборка PyTorch из `INSTALL.ps1`.

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\INSTALL.ps1
```

Если CUDA пока недоступна:

```powershell
.\INSTALL.ps1 -CpuOnly
```

## Полный цикл обработки

После скачивания PDF:

```powershell
.\RUN_GENERAL_ANALYTICS.ps1 -Device cuda -Method hdbscan
```

Для графового разбиения Louvain:

```powershell
.\RUN_GENERAL_ANALYTICS.ps1 -Device cuda -Method graph
```

Команды по отдельности:

```powershell
.\.venv\Scripts\python.exe -m sciintel.cli ingest
.\.venv\Scripts\python.exe -m sciintel.cli keywords
.\.venv\Scripts\python.exe -m sciintel.cli embed --device cuda --batch-size 16
.\.venv\Scripts\python.exe -m sciintel.cli hdbscan --device cuda --min-cluster-size 12 --min-samples 5 --reduction umap
.\.venv\Scripts\python.exe -m sciintel.cli graph-cluster --device cuda --k 15 --min-similarity 0.35 --resolution 1.0
```

### Семантические названия и проверка групп

После запуска HDBSCAN или Louvain открой страницу **«Тематические профили»** и нажми **«Сформировать / обновить семантические названия»**. Также доступен отдельный запуск из PowerShell: `.\BUILD_SEMANTIC_PROFILES.ps1`. Анализ привязан к текущему `run_id` и сохраняется в `artifacts/runs/<run_id>/semantic_profiles/`, поэтому профили от предыдущего запуска не смешиваются с текущими.

Интерпретация строится аналитически, без LLM: повторяющиеся непрерывные научные фразы извлекаются из названий и аннотаций, оцениваются поддержка фразы внутри группы, её выраженность в заголовках, отличие от других групп и TF-IDF-когерентность. При наличии канонической аннотации из метаданных arXiv она используется как основной текстовый источник; извлечённый PDF-текст остаётся резервным источником при отсутствии аннотации. Для крупных групп дополнительно проверяется наличие внутренних подтем.

Каждая карточка показывает семантическое название, подтверждённые аспекты, число публикаций, долю поддержки главной темы, среднее сходство документов с TF-IDF-центроидом и несколько наиболее репрезентативных статей. Репрезентативность определяется близостью title+abstract TF-IDF-вектора к центроиду группы. Рядом отображается состав исходных категорий arXiv — только как вспомогательный индикатор, а не как истинная разметка.

Статусы профиля — `STRONG_PROFILE`, `MODERATE_PROFILE`, `REVIEW_PROFILE`, `MIXED_TOPIC_REVIEW` и `INTERNAL_SUBTOPICS_DETECTED` — являются диагностическими категориями. `topic_profile_score` — эвристический индекс доказательности, **не калиброванная вероятность**. Если надёжного общего понятия не найдено, система не придумывает конкретное название, а помечает сообщество как смешанное или требующее проверки. Внутренние подгруппы показываются как диагностика и не меняют исходные назначения HDBSCAN/Louvain.

Артефакты профилирования:

- `group_topic_profiles.csv` — семантическое название и доказательные метрики каждой группы;
- `document_topic_analysis.csv` — сходство публикаций с центроидом, репрезентативные и периферийные документы;
- `topic_candidates.csv` — фразы-кандидаты и частота их поддержки;
- `internal_subtopics.csv` и `internal_subtopic_assignments.csv` — диагностика внутренних направлений;
- `topic_understanding_metadata.json` — параметры и ограничения анализа.

## Графовая модель

Для каждого документа строится вершина `Paper`. Для пары документов вычисляется cosine similarity между SPECTER-векторами. При kNN-графе для каждой вершины выбираются `k` ближайших соседей. Порог `min_similarity` удаляет слабые связи. В режиме mutual kNN ребро сохраняется, только если оба документа выбрали друг друга.

Louvain оптимизирует модульность взвешенного графа. Параметр `resolution` управляет масштабом сообществ: увеличение обычно приводит к большему числу более мелких групп. `min_community_size` переводит слишком маленькие сообщества в шум. Это самостоятельный графовый метод, его результаты не смешиваются с HDBSCAN.

В интерфейсе визуализируются:

- граф публикаций: узел = статья, ребро = семантическая близость;
- цвет узла = назначенная группа;
- граф тематических групп: узел = центроид кластера, ребро = cosine similarity центроидов в исходном SPECTER-пространстве.

## Где сохраняются данные

- `data/inbox/` — исходные PDF, разложенные по исходным темам;
- `data/metadata/` — манифест и случайные квоты arXiv;
- `data/processed/` — извлечённые тексты;
- `data/silab.sqlite3` — метаданные и назначения;
- `artifacts/embeddings/` — SPECTER-векторы и manifest;
- `artifacts/runs/<run_id>/` — назначения, профили, метрики, координаты и рёбра графа;
- `reports/` — автоматические тематические названия и отчёты.

## Визуальная система интерфейса

Интерфейс использует светлую нейтральную основу, тёмный текст с высоким контрастом и ограниченную систему акцентов: холодный сине-бирюзовый для основного действия, тёплый янтарный для вторичных акцентов. Для категориальных данных применяется дискретная палитра с различимыми оттенками; шум всегда серый. Для непрерывных метрик используется последовательная шкала одного цветового семейства, а не «радуга». Цвет не является единственным носителем информации: в графах и таблицах остаются подписи, размеры и hover-пояснения.

## Методологические оговорки

- Не задаём число кластеров заранее для HDBSCAN.
- Не используем исходную категорию arXiv как входной признак в SPECTER-вектор. Она нужна только для внешней проверки после кластеризации.
- Не используем координаты PCA/UMAP для вычисления cosine similarity.
- Не сравниваем silhouette в разных пространствах без явного указания пространства расчёта.
- Автоматические названия кластеров являются интерпретацией по текстовым признакам и должны сопровождаться примерами публикаций и оценкой уверенности.
- Хорошее совпадение с arXiv category не гарантирует научную тематическую корректность: проверяем также термины, репрезентативные статьи, устойчивость и смешанные группы.
