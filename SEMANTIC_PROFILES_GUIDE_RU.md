# Семантические названия и проверка тематических сообществ

## Быстрый запуск

1. Сначала выполните обычную кластеризацию HDBSCAN или Louvain.
2. Откройте панель `START_DASHBOARD.ps1`.
3. Перейдите в раздел **«Тематические профили»**.
4. Нажмите **«Сформировать / обновить семантические названия»**.
5. Откройте карточки сообществ и проверьте подтверждающие фразы, репрезентативные публикации и пограничные документы.

Альтернативный запуск из PowerShell:

```powershell
.\BUILD_SEMANTIC_PROFILES.ps1
```

Профили записываются рядом с результатами именно текущего запуска:

```text
artifacts/runs/<run_id>/semantic_profiles/
```

## Как получается название

Процедура не обращается к генеративной языковой модели. Она использует название статьи и аннотацию. При наличии канонической аннотации из метаданных arXiv эта аннотация рассматривается как основной текстовый источник; текст PDF используется для резервного извлечения, если аннотация отсутствует.

Для кандидатов в название рассчитываются поддержка фразы внутри сообщества, частота её появления в заголовках, отличие от других сообществ и статистическая выраженность. Выбираются устойчивые непрерывные научные понятия, а не просто наиболее частотные отдельные слова.

Для оценки однородности строятся TF-IDF-представления `title + abstract`. Считаются среднее и медианное сходство документов с центроидом, а также среднее попарное сходство. Репрезентативные публикации — документы, наиболее близкие к центроиду. Пограничные публикации — документы с наименьшим сходством; они показываются для ручной проверки, а не автоматически объявляются ошибками.

Для достаточно крупных сообществ дополнительно проверяется наличие внутренней структуры с помощью KMeans и Silhouette в TF-IDF-пространстве. Это только диагностика: HDBSCAN/Louvain labels не переписываются.

## Статусы

- `STRONG_PROFILE` — тема имеет выраженную поддержку и хорошую текстовую согласованность.
- `MODERATE_PROFILE` — есть содержательная тема, но свидетельств недостаточно для сильного статуса.
- `REVIEW_PROFILE` — найденные сигналы слабые; название нужно проверить.
- `MIXED_TOPIC_REVIEW` — одного устойчивого общего понятия не найдено.
- `INTERNAL_SUBTOPICS_DETECTED` — внутри сообщества выявлены устойчивые подтемы.

Индекс `topic_profile_score` — эвристическая сводка нескольких признаков, не калиброванная вероятность и не самостоятельная оценка качества.

## Какие файлы проверять

| Файл | Что в нём |
|---|---|
| `group_topic_profiles.csv` | Семантические названия, аспекты, поддержка, когерентность и статус |
| `document_topic_analysis.csv` | Сходство каждой публикации с центроидом и её подгруппа |
| `topic_candidates.csv` | Фразы-кандидаты и статистические свидетельства |
| `internal_subtopics.csv` | Названия и размеры обнаруженных подтем |
| `internal_subtopic_assignments.csv` | Привязка публикаций к диагностическим подтемам |
| `topic_understanding_metadata.json` | Параметры процедуры, количество канонических аннотаций и ограничения |

## Интерпретация

Название — это компактный индекс темы, а не исчерпывающее описание всего сообщества. Проверяйте его по нескольким независимым свидетельствам: заголовкам репрезентативных статей, аннотациям, поддерживающим фразам, пограничным статьям, внутренним подтемам и распределению исходных категорий arXiv. Категория arXiv является слабой внешней меткой, а не истинной научной разметкой.

Технический ID сообщества сохраняется для воспроизводимости и связи с исходным графом, но в пользовательском представлении основным названием является семантическая тема.
