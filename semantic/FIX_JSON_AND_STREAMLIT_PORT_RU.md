# Исправление Qwen JSON и запуска Streamlit

## Что было не так

1. В предыдущей версии Ollama-запрос генерации ограничивался `num_predict=560`, а проверка — `420`. Это слишком мало для полного обязательного JSON-профиля. В ответах длиной около 2 тыс. символов JSON обрывался внутри строки, после чего для всех сообществ использовались резервные названия.
2. Streamlit запускался строго на порту 8501. Если старый экземпляр уже занимал этот порт, новый процесс завершался.
3. Выбор десяти репрезентативных публикаций не отдавал предпочтения публикациям с доступными аннотациями, поэтому модель в основном видела заголовки, даже когда аннотации в группе были.

## Что исправлено

- Компактные JSON Schema с ограничениями длины строк и количества элементов.
- `num_predict`: 1100 для именования, 800 для критической проверки.
- Одна автоматическая повторная попытка при повреждённом/обрезанном JSON с увеличенным лимитом.
- Сохраняются `done_reason`, `eval_count`, фактический лимит токенов, длина ответа и статистика повторов в `topic_label_generation.json` → `labeler.ollama_runtime`.
- В evidence-модель передаются аннотации прежде title-only записей; отбор представительских документов теперь ищет документы с текстом по всему сообществу.
- По умолчанию увеличен лимит поиска аннотаций по заголовку OpenAlex до 300 и Crossref DOI-запросов до 100; положительный и отрицательный кэш сохраняется.
- Streamlit автоматически переходит на следующий свободный порт (8502, 8503 и т. д.), если 8501 занят. `-StrictPort` отключает автопереход.

## Установка

Распакуйте архив поверх существующей папки `semantic` в корне проекта с заменой файлов. Не удаляйте каталоги `reports`, `artifacts`, `.venv` или кэш аннотаций.

## Проверка и повторный запуск

```powershell
.\semantic\RUN_SEMANTIC_TESTS.ps1 -ProjectRoot (Get-Location).Path

.\semantic\RUN_TOPIC_LLM_LABELING.ps1 `
    -ProjectRoot (Get-Location).Path `
    -RunId "20261120_015622_graph_b63e68" `
    -SourceResult "20261126_030905_llm_labels" `
    -AbstractSource auto

.\semantic\RUN_TOPIC_EXPLORER.ps1 -ProjectRoot (Get-Location).Path
```

Указан исходный каталог `20261126_030905_llm_labels`, поскольку это результат до неудачного прохода `_semantic_reviewed`. Скрипт создаст отдельный новый снимок и обновит `latest.json`. Leiden, граф, SPECTER и UMAP повторно не запускаются.

## Диагностика

- `topic_label_generation.json` содержит полный статус по каждой группе.
- `labeler.ollama_runtime.last_call.done_reason == "length"` означает достижение лимита генерации; после исправления должна сработать повторная попытка.
- `invalid_json_responses` и `retries` показывают число проблемных ответов/повторов.
- `abstract_enrichment_report.json` показывает, сколько аннотаций удалось получить по каждому источнику и сколько запросов завершилось ошибками.
- `paper_evidence.csv` позволяет проверить источники аннотаций для отдельных `document_id`.

Никакой локальный полный текст не отправляется во внешние API. Для OpenAlex/Crossref используются идентификаторы и ограниченный поиск по публичным заголовкам; передаётся только заголовок при отсутствии идентификатора.
