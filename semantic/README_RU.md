# Автоматическое обнаружение тематических групп + Streamlit

Модуль добавляется в корень проекта `Scientific_articles_processing`. Он использует уже сохранённый граф и существующие SPECTER-векторы; исходные артефакты не перестраиваются и не перезаписываются.

## Принцип: число групп не задаётся

В коде нет `n_clusters`, фиксированного списка из десяти групп или постфильтра, который оставляет заданное количество тем. Выполняется sweep по `resolution` алгоритма Leiden. Для каждого значения Leiden запускается несколько раз с разными seed. Выбранное разбиение определяется по совокупности:

- устойчивость между seed (средний ARI);
- silhouette в исходном SPECTER-пространстве с cosine distance;
- штрафы за singleton-группы, одну чрезмерно крупную группу и единственное сообщество.

Устойчивость и silhouette переводятся во внутрипоисковые процентильные ранги и усредняются с равным весом. Модулярность сохраняется как диагностическая метрика, но не ранжируется между разными `resolution`: при изменении resolution меняется сама оптимизируемая функция, поэтому прямое сравнение таких значений может смещать выбор в пользу грубых разбиений. Ни число групп, ни диапазон числа групп в оценку не входят. Коэффициенты и все проверенные варианты публикуются в `summary.json` и `resolution_sweep.csv`. Это открытая эвристика model selection, а не математическая гарантия единственного верного числа тем.

## Что требуется

В корне проекта должны находиться:

```text
.venv/                         # существующее окружение Python
artifacts/runs/<RUN_ID>/
    clusters.csv
    graph_edges.csv
    metrics.json
artifacts/embeddings/sentence-transformers_allenai-specter/
    manifest.json
    vectors.npy
```

`clusters.csv` должен содержать `document_id` и `title`; `graph_edges.csv` — `source_id`, `target_id`, `similarity`. Порядок векторов восстанавливается по ID из `manifest.json`, а не угадывается по порядку CSV.

Для названий и ключевых фраз скрипт дополнительно ищет CSV/TSV/Parquet/Excel/JSONL/JSON с идентификаторами и аннотациями/текстами в `data/` и `artifacts/`; также пытается извлекать abstract/front matter из локальных PDF в `data/` (для PDF нужен уже установленный `PyMuPDF` или `pypdf`, этот компонент необязателен). Сопоставление выполняется по `document_id`, DOI, OpenAlex ID и другим известным идентификаторам, а не по номеру строки. Если локальной аннотации нет, в режиме `auto` программа пытается получить её по DOI/OpenAlex ID из OpenAlex; затем может использовать ограниченный резервный поиск Crossref. Для записей вообще без DOI/OpenAlex ID включается ограниченный OpenAlex-поиск по заголовку (до 100 запросов по умолчанию). Лимит title-search распределяется по доменам по кругу, чтобы не обрабатывать только начало корпуса. Найденная работа принимается только при высокой метрике совпадения нормализованного заголовка (не ниже 0.90); слабые совпадения отбрасываются. Отрицательные результаты повторно проверяются через 90 дней. Если источники не содержат аннотацию, профиль строится по заголовкам, что явно отражается в отчёте.

## Семантическое именование локальной языковой моделью

Для создания названий и описаний используется отдельная instruction-модель через локальный Ollama API. По умолчанию выбран `qwen3.5:4b`: сборка Ollama занимает около 4 GB, опубликована под Apache 2.0, поддерживает 201 язык и запускается локально. На RTX 4070 8 GB её следует запускать с коротким контекстом (в этом модуле установлен `num_ctx=4096`).

SPECTER не заменяется и не используется как генератор текста: он остаётся моделью векторного представления научных публикаций. Выбор репрезентативных публикаций сочетает ближайшие к центроиду документы, покрытие доменов и farthest-first разнообразие. В модель передаются не только ключевые фразы и домены, но и до десяти репрезентативных заголовков с найденными аннотациями/выдержками. Числа доступных аннотаций и покрытие каждой темы рассчитываются отдельно.

На каждую тему выполняются два прохода одной и той же модели:
1. генерация названия, описания, исследовательского ядра, подтем, методов, объектов исследования и оценки тематической неоднородности;
2. отдельный критический проход по тем же источникам: поиск неподтверждённых утверждений, ошибочных сокращений, пропущенных направлений и чрезмерно узких названий. Это не независимая проверка другой моделью, а второй проход той же Qwen.

Если доказательств недостаточно, тема получает статус `review_required`; неподтверждённые утверждения не скрываются. Если вызов модели завершился ошибкой, применяется явный резервный вариант по ключевым фразам с отметкой `generation_failed_fallback`, чтобы единичный тайм-аут не уничтожил весь запуск.

LLM работает строго после Leiden. Она не меняет эмбеддинги, рёбра, `resolution`, количество сообществ или назначения документов. Для аудита сохраняются evidence, черновик генерации, выбранные подтверждающие заголовки и результат критического прохода в `topic_label_generation.json`, а также model digest и параметры вызова в `summary.json`.

### Подготовка Ollama (один раз)

1. Установите Ollama для Windows с официального сайта: https://ollama.com/download
2. Откройте новое окно PowerShell и скачайте модель:

```powershell
ollama pull qwen3.5:4b
ollama list
```

3. Проверьте доступность локального API:

```powershell
Invoke-RestMethod http://127.0.0.1:11434/api/tags
```

Не требуется устанавливать `ollama` или `transformers` в `.venv` проекта. Интеграция обращается к Ollama стандартной библиотекой Python.

Для принудительного использования эвристического именования без модели:

```powershell
.\auto_topic_discovery_app\RUN_AUTO_TOPIC_DISCOVERY.ps1 -Labeler heuristic
```

Можно выбрать другую установленную Ollama-модель и адрес сервера параметрами `-LabelerModel` и `-OllamaUrl`.


### Обогатить evidence и переименовать уже найденные темы (без повторной кластеризации)

Для текущего результата `20261126_030905` не нужно повторять sweep Leiden или строить UMAP. Скрипт снова загрузит существующий SPECTER-кэш только для отбора репрезентативных публикаций и расчёта центроидов, затем найдёт недостающие аннотации, выполнит два прохода Qwen и создаст отдельную версию результата:

```powershell
.\auto_topic_discovery_app\RUN_TOPIC_LLM_LABELING.ps1 `
    -ProjectRoot (Get-Location).Path `
    -RunId "20261120_015622_graph_b63e68" `
    -SourceResult "latest"
```

`latest` берёт каталог из `reports/auto_topic_discovery/<RUN_ID>/latest.json`. Скрипт создаёт отдельную новую папку с суффиксом `_semantic_reviewed`, не изменяя исходный результат. Обновлённый каталог автоматически становится последним для Streamlit. Исходные `cluster_id`, назначения документов, resolution, sweep и координаты карты сохраняются без изменений. Кэш найденных аннотаций хранится отдельно в `artifacts/cache/topic_abstracts/paper_abstract_cache.json` и переиспользуется при следующих запусках.

Параметры источников:

```powershell
# Локальные таблицы/PDF + OpenAlex + ограниченный Crossref fallback (по умолчанию)
.\auto_topic_discovery_app\RUN_TOPIC_LLM_LABELING.ps1 -AbstractSource auto

# Только локальные файлы, без сетевых запросов
.\auto_topic_discovery_app\RUN_TOPIC_LLM_LABELING.ps1 -AbstractSource local

# Только OpenAlex и кэш, без локального поиска
.\auto_topic_discovery_app\RUN_TOPIC_LLM_LABELING.ps1 -AbstractSource openalex

# Не получать аннотации; использовать существующие заголовки
.\auto_topic_discovery_app\RUN_TOPIC_LLM_LABELING.ps1 -AbstractSource off
```

Базовые запросы OpenAlex доступны без API-ключа. Для регулярной обработки корпуса и увеличенного дневного лимита рекомендуется получить бесплатный ключ в аккаунте OpenAlex и задать его через переменную окружения `OPENALEX_API_KEY`; контактный email задаётся через `OPENALEX_MAILTO`. Актуальные лимиты и порядок авторизации могут меняться — сверяйте их с официальной документацией OpenAlex. По умолчанию установлены пределы: 50 пакетных запросов по идентификаторам (до 100 ID на пакет), 100 отдельных поисков по заголовку для записей без устойчивых ID (порядок выравнивается по доменам) и 50 резервных DOI-запросов Crossref; тайм-аут OpenAlex — 15 секунд. Если OpenAlex недоступен, оставшиеся удалённые запросы останавливаются, чтобы не повторять длительные сетевые тайм-ауты.

Если в `clusters.csv` отсутствуют DOI/OpenAlex ID и нужно расширить поиск по заголовкам, лимит можно увеличить явно (это увеличит число обращений к внешнему API и расход дневного бюджета OpenAlex):

```powershell
.\auto_topic_discovery_app\RUN_TOPIC_LLM_LABELING.ps1 `
    -ProjectRoot (Get-Location).Path `
    -RunId "20261120_015622_graph_b63e68" `
    -SourceResult "latest" `
    -MaxOpenAlexTitleLookups 250
```

Обычный запуск безопасно ограничен 100 поисками. Положительный кэш переиспользуется, отрицательный кэш заголовков истекает через 90 дней.

**Передача данных:** OpenAlex/Crossref получают DOI или OpenAlex ID. Только для записей без этих идентификаторов OpenAlex может получить заголовок публикации для поиска; полный текст и локальные аннотации корпуса на внешний API не загружаются. Аннотации извлекаются из открытых метаданных и хранятся в локальном кэше проекта. Отрицательные результаты title-search кэшируются на 90 дней, затем перепроверяются. Часть аннотаций Crossref может иметь отдельные авторские/издательские ограничения; CSV с аннотациями предназначен для внутреннего анализа и не должен автоматически публиковаться как открытый корпус. Локальная Ollama получает evidence через `127.0.0.1`; при ручной замене `OllamaUrl` на удалённый сервер данные будут отправляться на него.

## Установка

Распакуйте архив в корневую папку проекта, сохранив вложенную папку `auto_topic_discovery_app`. Откройте PowerShell в корне проекта. Исходные скрипты можно оставить в этой папке: запускатели сами используют корень проекта и его `.venv`.

```powershell
Set-ExecutionPolicy -Scope Process Bypass
```

Запускатель проверяет версии и при необходимости восстанавливает совместимый набор: `igraph==1.0.0`, `leidenalg==0.12.0`, `yake==0.7.3`, `umap-learn==0.6.0`, Streamlit и Plotly. YAKE `0.7.3` соответствует требованию установленного `scientific-intelligence-lab 1.0.0`; предыдущий установщик ошибочно понизил его до `0.4.8`. UMAP `0.6.0` также восстанавливается до версии, которая стояла в окружении до установки надстройки. Проверка запускается отдельным Python-файлом, поэтому Windows PowerShell 5.1 не должен повреждать кавычки в многострочном `python -c`.

```powershell
.\auto_topic_discovery_app\RUN_AUTO_TOPIC_DISCOVERY.ps1
```

При первом запуске используется контрольный граф `20261120_015622_graph_b63e68`. Диапазон resolution, число проверяемых точек, число seed-повторов и seed можно менять:

```powershell
.\auto_topic_discovery_app\RUN_AUTO_TOPIC_DISCOVERY.ps1 `
    -ResolutionMin 0.35 `
    -ResolutionMax 2.0 `
    -ResolutionSteps 12 `
    -Repeats 5 `
    -Seed 42
```

Это не означает 12 или 5 кластеров: `ResolutionSteps` — число проверяемых значений resolution, `Repeats` — число повторов для оценки устойчивости.


### Важно: получение аннотаций всего корпуса

`100/1870` — это не ограничение количества аннотаций в проекте и не результат именования. Это число документов, для которых сборщик нашёл аннотацию/текст. При отсутствии персонального ключа OpenAlex использует общий бюджет по IP; если API возвращает `429`, модуль прекращает обращения к OpenAlex, но теперь продолжает независимый Crossref fallback.

Новая версия ищет недостающие записи в Crossref по DOI, а если DOI отсутствует — по библиографическому заголовку (`query.bibliographic`). Аннотация прикрепляется только при строгом совпадении заголовка (score ≥ 0.92). Поэтому количество найденных аннотаций должно вырасти, но не может гарантированно достигнуть 1870: издатели не всегда депонируют abstract в Crossref/OpenAlex, а часть работ может быть доступна только в PDF.

По умолчанию запускается до 900 OpenAlex title searches и до 1870 Crossref title searches. Для полного покрытия бюджета OpenAlex рекомендуется свой бесплатный API-ключ: прямой `/works?search=` запрос стоит около $1 за 1000 запросов, бесплатный ключ даёт $1 дневного бюджета; поэтому 900 поисков оставляют небольшой запас на другие вызовы. При отсутствии ключа чужой/общий бюджет по IP может быть уже исчерпан. Официальные правила и цены: https://help.openalex.org/api/authentication/ и https://help.openalex.org/access/example-costs/.

PowerShell:

```powershell
# Вставьте свой ключ только локально; не публикуйте его и не отправляйте в чат.
$env:OPENALEX_API_KEY = "<YOUR_OPENALEX_KEY>"
$env:OPENALEX_MAILTO = "<YOUR_EMAIL>"

.\semantic\RUN_TOPIC_LLM_LABELING.ps1 `
    -ProjectRoot (Get-Location).Path `
    -RunId "20261120_015622_graph_b63e68" `
    -SourceResult "20261126_030905_llm_labels" `
    -AbstractSource auto `
    -MaxOpenAlexTitleLookups 900 `
    -MaxCrossrefTitleLookups 1870 `
    -MaxCrossrefLookups 1870
```

Запросы Crossref выполняются последовательно и могут занять несколько минут. Положительные результаты записываются в кэш; следующий запуск не должен заново запрашивать уже найденные аннотации. Отсутствующий в метаданных издателя abstract невозможно получить только настройкой лимита — для таких публикаций потребуется локальный PDF/полный текст или другой легальный открытый источник.

## Streamlit

После успешного анализа:

```powershell
.\auto_topic_discovery_app\RUN_TOPIC_EXPLORER.ps1
```

Откроется локальный адрес `http://localhost:8501`. В интерфейсе есть:

- карта публикаций UMAP (PCA fallback), с раскраской по тематическим группам или доменам;
- динамический каталог тем с количеством публикаций, описанием, подтемами, методами и объектами исследования;
- ключевые фразы YAKE, RAKE и contrastive TF-IDF;
- репрезентативные статьи с доступными аннотациями и источником каждого текста;
- покрытие аннотациями по каждой группе и общая сводка;
- панель критической проверки: решение, уровень поддержки, неподтверждённые утверждения и пропущенные направления;
- публикации, которыми сама модель обосновала название;
- оценка тематической неоднородности и пограничные документы;
- график и таблица подбора resolution;
- ручная корректировка названия темы с сохранением локального override;
- экспорт назначений, профилей, summary и evidence с аннотациями.

2D-координаты применяются только для визуализации. Они не участвуют в оценке кластеризации.

## Проверка качества названий

Генеративная модель может ошибочно обобщать неоднородную группу или переинтерпретировать редкий термин. Критический проход выполняет та же модель, поэтому он снижает число очевидных ошибок, но не является независимой экспертизой. Решение `accepted` не следует трактовать как доказанную истинность метки. При нулевом покрытии аннотациями модель получает заголовки и ключевые фразы; такая группа получает слабую доказательную базу. Все evidence, выбранные подтверждающие заголовки и замечания сохраняются в `topic_label_generation.json`. Автоматическое название является интерпретацией, а не ground truth.
